## 一、什么是 RTOS？为什么不用裸机 while(1)？

### 裸机程序（你写过的）

```c
while(1) {
    读传感器();
    处理数据();
    发送结果();
}
```

问题：读传感器花了 5ms，处理数据花了 3ms，发送花了 10ms——**你没法同时做两件事**。如果传感器每 5ms 就要读一次但你正在处理数据，就丢了。

### RTOS 的做法

把程序拆成多个**任务**（Task），每个任务是一个独立的 `while(1)` 循环。RTOS 内核（调度器）负责在任务之间**快速切换**，让你感觉它们在同时跑。

```
任务1: 读加速度计    → 每 50ms 跑一次
任务2: 读温度        → 每 100ms 跑一次
任务3: 处理所有数据  → 每 50ms 跑一次
```

### 你的项目里

6 个任务同时跑，调度器按优先级决定谁先跑。AccelSensor 优先级 2，Processor 优先级 3——Processor 有数据要处理时，调度器会让它**抢断**传感器任务。

## 二、任务、优先级、调度

### 任务就是函数

```c
void vAccelSensorTask(void *pv) {
    for(;;) {  // 死循环 = 任务永远运行
        干一件事();
        vTaskDelay(50ms);  // 主动让出 CPU，50ms 后回来
    }
}
```

### 优先级

数字越大越优先。你的项目里：

```
Cmd     优先级 4  ← 最高（命令必须立刻响应）
Proc    优先级 3  ← 数据处理优先于采集
Accel   优先级 2  ← 传感器们
Temp    优先级 2
Light   优先级 2
Mon     优先级 1  ← 最低（监控不急）
```

调度器的规则：**高优先级的任务就绪时，立即抢断低优先级的任务**。

### 面试话术

"用了 FreeRTOS 的抢占式调度。三个传感器同优先级 2，轮转执行。Processor 优先级 3，一旦队列有数据就抢占 CPU。Monitor 优先级 1 最低，只在没人干活时跑。"

## 三、队列（Queue）—— 任务间怎么传数据

### 问题

任务 A 产生了数据，任务 B 要处理。怎么传？

- 方案 1：全局变量。❌ 不安全——A 写完一半 B 就来读，数据错乱。
- 方案 2：队列。✅ FreeRTOS 提供的线程安全通道。

### 队列就像一个管道

```
SensorTask ──[ 数据1 | 数据2 | 数据3 | ... ]──> ProcessorTask
              ← 最多 32 个 ← （满了就丢弃旧的）
```

两种操作：
- `xQueueSend()` —— 往队列**放**数据（生产者）
- `xQueueReceive()` —— 从队列**取**数据（消费者）

### 你的项目里

```c
// 传感器任务：往队列放
xQueueSend(xAccelQueue, &data, 0);
//                                 ↑ 0 = 如果队列满了，不等待，直接丢弃

// 处理器任务：从队列取
while(xQueueReceive(xAccelQueue, &raw, 0) == pdPASS) {
    // 一直取，直到队列空
}
```

### 面试话术

"三个独立队列解耦了传感器和处理器。生产者不关心谁在消费，消费者不关心谁在生产。队列深度 32 提供了约 1.6 秒的缓冲窗口。"

## 四、互斥锁（Mutex）—— 保护共享数据

### 问题

两个任务同时读写同一个变量：

```c
任务A: g_config.sensor_mask |= 0x01;  // 开传感器0
任务B: g_config.sensor_mask &= ~0x02; // 关传感器1
```

如果同时执行，结果不可预测。这叫**竞态条件**（Race Condition）。

### Mutex 就像厕所门

```c
xSemaphoreTake(xConfigMutex, portMAX_DELAY);  // 锁门
// 安全区内操作共享变量
g_config.anomaly_threshold = 5.0;
xSemaphoreGive(xConfigMutex);                 // 开门
```

同一时刻只有一个任务能进安全区。其他任务在门口排队。

### 你的项目里

每个任务读/写 `g_config`（全局配置）时都要先拿锁。关键点：**持锁时间极短**（几个赋值语句就释放），不会影响实时性。

### 面试话术

"mutex 临界区只保护配置结构体的读写，几个赋值语句就释放，持锁时间 < 1μs。绝不持锁做 I/O 或耗时计算。"

## 五、滑动窗口移动平均滤波

### 问题

传感器数据有噪声。加速度计读出来可能是 9.78、9.85、9.72、9.80...实际是 9.8。怎么去掉抖动？

### 方法：取最近 5 个值的平均数

```
原始数据流: 9.78  9.85  9.72  9.80  9.83
               ↓
          (9.78+9.85+9.72+9.80+9.83) / 5 = 9.796

新数据 9.75 来了:
抛弃最旧的 9.78:
窗口变成: 9.85  9.72  9.80  9.83  9.75
          (9.85+9.72+9.80+9.83+9.75) / 5 = 9.790
```

- 窗口越大 = 越平滑但响应越慢
- 窗口越小 = 响应快但噪声大
- 你的项目选 5：工程折中值

### 代码实现（环形缓冲区）

```c
float history[5];    // 存最近 5 个值
int idx = 0;         // 当前写入位置

// 每次新数据：
history[idx] = 新数据;
idx = (idx + 1) % 5;  // 循环，0→1→2→3→4→0

// 计算平均：
float sum = 0;
for(int i = 0; i < 5; i++) sum += history[i];
float filtered = sum / 5;
```

## 六、异常检测（3σ 准则）

### 直觉

正常情况下加速度计读数在 9.8 附近 ±0.1 波动。突然读到 15.2——这显然是异常。

### 怎么用数学判断

1. 算均值：窗口内 5 个值的平均 = 9.8
2. 算标准差（衡量"正常波动范围"）：std = 0.08
3. 判断：新值和均值的差距超过 3×标准差？

```
|15.2 - 9.8| = 5.4
3 × 0.08 = 0.24
5.4 > 0.24 → 异常！标记
```

### 为什么是 3？

正态分布规律：
- 1σ 内：68% 的正常数据
- 2σ 内：95%
- 3σ 内：**99.7%**

超出 3σ 的，大概率不是噪声而是真异常（传感器故障、碰撞、环境突变）。

```c
if (fabsf(raw - mean) > threshold * std) {
    anomaly_flag = 1;  // 标记异常
}
```

`threshold` 默认 3.0，可通过命令 `threshold 2.0` 调敏感。

│  优先级2               │   优先级3           │
│                        │       │            │
│  [LightTask]  ──Queue──┘       │ Queue      │

│  优先级2                      ▼            │
│                        [MonitorTask]        │

数据流向：**传感器 → 队列 → 处理器 → 队列 → 监控**

## 八、基础知识速查表

| 概念 | 一句话 | 代码关键字 |
|------|--------|-----------|
| **任务 (Task)** | 独立的 while(1) 函数 | `xTaskCreate()` |
| **调度器 (Scheduler)** | 决定谁跑谁等的裁判 | `vTaskStartScheduler()` |
| **优先级** | 数字越大越优先，高的可以抢低的 | `PRIORITY_XXX` |
| **队列 (Queue)** | 任务间传递数据的管道 | `xQueueSend/Receive` |
| **互斥锁 (Mutex)** | 保护共享变量，同时只能一个人访问 | `xSemaphoreTake/Give` |
| **移动平均** | 取最近N个值的平均数，去噪声 | `moving_average()` |
| **标准差** | 衡量数据波动大小的指标 | `std_dev()` |
| **3σ 异常检测** | 偏离均值超过3倍标准差的判为异常 | `anomaly_flag` |
| **vTaskDelayUntil** | 精确周期运行 | `vTaskDelayUntil(&last, period)` |
| **环形缓冲区** | 固定大小数组，写满后覆盖最旧的 | `idx = (idx+1) % 5` |
